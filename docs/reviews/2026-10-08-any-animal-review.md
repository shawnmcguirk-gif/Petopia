# Independent review: any kind of animal (689129a..806f64e)

Reviewer: separate Opus 5.5 agent, 2026-10-08. Read-only. No tests were re-run (the VM has no Postgres or npm registry); the iMac runner logs in `Axiom/runner/results/1791455*` were read instead.

**Verdict: READY WITH NOTES.** Nothing breaks the live dog/cat animals, ref.* stays free of household text, and the inbox regex is safely escaped. But several user-facing defaults for the new species are wrong (feeding suggested weekly, daily teeth for horses and rabbits, no weight slip-guard for small animals). Fix those in a follow-up migration 016 before Ryan adds his fish or a rabbit. No must-fix items.

## Checked and found fine

- **Live dog/cat animals:** `animal.module_code` is untouched. Dog/Cat get `module_code` 'dog'/'cat' via `UPDATE ... WHERE module_code IS NULL`. Old clients posting `species:'dog'` still resolve, and db.test's `parrot -> unicorn` change is correct now that Parrot exists. care.ts/measurements.ts read `animal.module_code`, so they behave the same.
- **Migration order and FK:** the column is added (FK to `species_module.code`), then modules, species and the UPDATE run. Every UPDATE target exists. Counts match HANDOFF (43 PET with a module, 21 WILD, 10 modules, per the live log). Each file is applied once in one transaction (`psql -1`). No WILD name collides with a PET name ("Frog" vs "Common frog", "Rat", "Hedgehog" are all distinct, and nothing in WILD is listed).
- **RLS / ref.\*:** no request path writes to `ref.*`. Typed text lives only in `animal.animal.ext` (RLS-protected), as the DB test asserts. `GET /api/species` is household-guarded and read-only (`x.r`). `species_name` never reaches a Claude prompt (reader.ts sends only the document) and React escapes it on display.
- **Inbox regex:** the needle is lowercased in SQL first, then escaped with the full MDN set, and `$&` is right. `-` and `/` need no escaping outside a class. The pattern is `(^|[^a-z])literal s?($|[^a-z])`, with no nested quantifiers, so there is no ReDoS. The needle is ≤80 chars and AJV checks maxLength before trim.
- **"Other animal" rule:** required on create and on every `ext` PATCH. Whitespace-only is refused after trim. The species of an existing animal cannot be changed (`species`/`module_code` are not in `known`). The PATCH fix (806f64e) is correct but **not yet deployed**. The live web never sends `ext` on PATCH, so the live exposure is API-only.
- **AnimalForm state:** the select shows "Choose…" whenever Dog/Cat is pressed. `otherName` survives switching but is only sent while Other is selected. `canSave` is right for add and edit. The fetch is cancelled on unmount, and the fallback appears only when the list is short. Labels and `aria-pressed` are present.
- **Species and groups:** scientific names spot-checked correct (Bala shark, Tiger barb *Puntigrus tetrazona*, Angelfish, Koi *C. rubrofuscus*, Axolotl, Ball python). Torpedo barb = *Sahyadria denisonii* is a reasonable reading of "torpedoes", and HANDOFF correctly flags it as unconfirmed. Poultry sits under Birds and equines under Mammals in the picker: odd neighbours, but not wrong. Equine vaccine names (equine influenza, tetanus) are uncontroversial.
- **Spec rules:** nothing is auto-created (defaults are still only suggestions). Provenance is unaffected (ref data, not facts). WILD rows have no module, so they cannot be added as pets, which matches sec 3.8 deferring wildlife to v2.
